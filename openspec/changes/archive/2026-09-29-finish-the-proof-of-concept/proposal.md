# Finish the proof of concept

Beans epics: `openspec-schema-manager-sx6d` (Update detection),
`openspec-schema-manager-iy57` (Acceptance end to end suite),
`openspec-schema-manager-fpti` (README, demos and help).

## Why

Everything the briefing asks for is built. What is left is the difference
between a thing that works and a thing someone else can pick up: an honest
answer to the one question the briefing left open, a suite that checks the
acceptance criteria rather than a claim that they pass, and a README that says
what ossm is without making anyone read eight milestones of beans.

Update detection is the open question. OpenSpec records no provenance for an
installed schema, so ossm cannot ask it whether a project's copy is behind. The
briefing says to decide what is honest and either ship it on that basis or leave
it out and say so. Leaving it out entirely wastes what ossm does know; shipping
it as "update available" would be a lie.

## What Changes

- The Project tab can compare an installed schema against a registry entry that
  declares the same name, and reports one of four things: identical, differs,
  cannot be compared because nothing in the registry matches, or cannot be
  compared because the source cannot be reached.
- A difference is reported as a difference and never as "an update is
  available". ossm cannot tell an upstream change from a local edit, and the
  message says so.
- Comparison is asked for, not run on every project read, because it fetches.
- The acceptance criteria in the briefing become end to end cases, one per
  criterion, in a file that names them.
- A README that says what ossm is, what it does, how to run it, and what it
  cannot do.
- Recorded terminal demos, generated from VHS tapes checked into the repository
  so they can be regenerated.
- A key reference in the README covering every screen, generated from the same
  `Keys()` the help overlay reads, so the two cannot drift.

## Capabilities

### New Capabilities

- `update-detection`: what comparing an installed schema can claim, and what it
  refuses to claim.
- `acceptance`: the briefing's acceptance criteria as checkable statements.

### Modified Capabilities

- `project-view`: the Project tab gains the comparison action.

## Impact

- New: comparison in `internal/source`, its action in the Project screen,
  `test/e2e/acceptance_test.go`, a README, `demo/` with VHS tapes, and a
  generated key reference.
- The recorded demos need VHS, which is in nixpkgs and in the dev shell. They
  are regenerated by hand, not by the gate: recording a terminal is slow and
  a gate that takes minutes stops being run.
- Nothing about update detection is written to disk. ossm still keeps no record
  of what is installed; comparison reads the project, fetches the source and
  compares, every time it is asked.
